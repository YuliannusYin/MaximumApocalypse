## 一、检定系统

### 1.1 潜行检定

潜行检定用于判定玩家在地块上是否避开怪物的察觉。流程包含 4 个节点，对应 3 个 trigger（详见 §4.6.8 检定类 trigger）。

**输入参数**：可选传入一个地块参数；未传时使用玩家当前所在地块。

**计算公式**：潜行值 = 玩家潜行值 −（地块上的怪物总数 + 该地块的怪物标记数）。其中「玩家潜行值」由角色卡正反面状态决定（饥饿翻面后采用饥饿状态潜行值）。

**4 节点流程**：

| 节点 | trigger 名 | 说明 |
|------|------------|------|
| 1 | 潜行检定前（before_sneak_judge） | 可设置 skip_judge 跳过投骰 |
| 2 | 系统投骰 | 若未跳过，调用通用检定投两颗骰子，点数 ≤ 潜行值则成功 |
| 3 | 潜行检定时（on_sneak_judge） | 可修改 event.result |
| 4 | 潜行检定后（after_sneak_judge） | 结果已确定 |

**结果处理**：

- 潜行检定成功 → 无事发生。
- 潜行检定失败 → 移除该地块上的所有怪物标记，每移除 1 个怪物标记就抓 1 张怪物卡。若怪物牌堆已抓空，重洗怪物弃牌堆并组成新的怪物牌堆。

**面包车油耗**：在面包车地块执行潜行检定时，潜行值需额外扣减该地块当前怪物标记数（与一般地块一致），不再单独计算「油耗」。代码未为面包车实现独立的油耗机制；旧文档中「面包车油耗」表述已废弃，统一按上述公式处理。

**block 字段**：检定事件 schema 含 `block` 字段（事件结构详见 [GameSystem/Core/EventSystem.md](../GameSystem/Core/EventSystem.md)），表示本次检定所针对的地块；trigger 钩子可读取此字段以应用地块级效果。

**skip_judge**：节点 1 与节点 2 之间通过 `skip_judge` 标志传递是否跳过投骰；技能可在「潜行检定前」节点将该标志置为真，使系统跳过投骰直接进入节点 3。

### 1.2 怪物生成检定

怪物生成检定在玩家回合的「怪物出生」阶段执行（详见 [02_开局与流程.md](02_开局与流程.md)）。流程包含 5 个节点。

**5 节点流程**：

| 节点 | trigger 名 | 说明 |
|------|------------|------|
| 1 | 怪物出生检定前（before_spawn_judge） | 可设置 skip_judge 跳过投骰 |
| 2 | 系统投骰 | 若未跳过，调用通用检定投两颗骰子，记录点数 |
| 3 | 怪物出生检定时（on_spawn_judge） | 可修改 event.result |
| 4 | 怪物出生检定后（after_spawn_judge） | 结果已确定 |
| 5 | 结果处理：匹配地块 | 遍历所有存活且已展示地块，命中后施加效果 |

**结果处理**：遍历所有存活且已展示的地块，比对地块的怪物生成点数与投骰点数：

- 命中且该地块怪物标记数 < 3 → 该地块增加 1 枚怪物标记。
- 命中且该地块怪物标记数 = 3 且地块上有玩家 → 该地块每个存活的玩家各抓 1 张怪物卡（沿用抓取怪物卡流程，触发对应 trigger）。

### 1.3 通用检定

通用检定是基础投骰方法：投两颗六面骰（每颗 1–6），返回两骰点数之和。供潜行检定、怪物生成检定及部分卡牌技能复用。该方法本身不挂 trigger、不输出日志，调用方自行负责日志输出与 trigger 编排。

## 二、射程系统（唯一权威定义）

### 2.1 射程枚举

代码使用以下字符串值作为射程字段值；本章建立中英映射，正文采用中文名：

| 中文 | 英文键名 | 备注 |
|------|----------|------|
| 无 | none | 仅怪物使用；玩家射程不含此值 |
| 短距离 | short | |
| 中距离 | medium | |
| 长距离 | long | 玩家与怪物的范围语义不同，见 §2.2 |
| 无限 | infinity | |

### 2.2 各射程范围定义

**距离单位**：曼哈顿距离（详见 §2.3）。「同地块」即距离为 0；「上下左右相邻」即距离为 1。

**玩家视角**（以玩家所在地块为中心查询）：

| 射程 | 距离范围 | 含义 |
|------|----------|------|
| 短距离 | d = 0 | 仅同地块 |
| 中距离 | 0 ≤ d ≤ 1 | 同地块及其上下左右四向相邻地块 |
| 长距离 | 1 ≤ d ≤ 2 | **不含同地块**；距离 1 与距离 2 的地块 |
| 无限 | 任意 | 场上所有存活地块 |

> 注：玩家长距离「不含同地块」是设计意图——长距离武器无法威胁同地块目标。

**怪物视角**（以纠缠玩家所在地块为中心查询）：

| 射程 | 距离范围 | 含义 |
|------|----------|------|
| 无 | — | 仅攻击纠缠玩家本身 |
| 短距离 | d = 0 | 同地块的所有玩家 |
| 中距离 | 0 ≤ d ≤ 1 | 同地块及其上下左右相邻地块的所有玩家 |
| 长距离 | 0 ≤ d ≤ 2 | **含同地块**；距离 0、1、2 的地块上的所有玩家 |
| 无限 | 任意 | 场上所有玩家 |

> **关键差异**：玩家长距离**不含**同地块（d ≥ 1），怪物长距离**含**同地块（d ≥ 0）。此差异由 §2.4 的 `for_monster` 参数控制。

### 2.3 距离计算

- **曼哈顿距离**：`distance_to(other)` 返回 `|x1 − x2| + |y1 − y2|`。x 为列、y 为行，对应任务地图矩阵的 `map[y][x]`。
- **相邻地块查询**：`get_adjacent_blocks()` 返回当前地块上下左右四向相邻且存活的地块数组，**不含对角线**。若邻居坐标无地块或地块已摧毁，则不包含。
- 相邻关系是移动、射程计算的基础；所有距离查询均基于曼哈顿距离，不使用切比雪夫距离或对角移动。

### 2.4 范围内目标查询

**地块查询**：`get_blocks_in_range(range_str, for_monster)` 返回指定射程内所有存活地块数组。`for_monster` 参数语义：

- `for_monster = true`（怪物查询）：长距离时距离范围 0 ≤ d ≤ 2（含同地块）。
- `for_monster = false`（玩家查询，默认）：长距离时距离范围 1 ≤ d ≤ 2（不含同地块）。

短距离、中距离、无限三种射程的语义不因 `for_monster` 参数变化。

**玩家查询**：`get_players_in_range(range_str, for_monster)` 先调用 `get_blocks_in_range` 取得地块数组，再聚合各地块上所有存活玩家。`for_monster` 参数语义同上。

**怪物攻击流程使用方式**：怪物行动时若射程为「无」，直接对纠缠玩家造成伤害，不调用地块查询；否则以纠缠玩家所在地块为中心，调用 `get_players_in_range(range, true)` 取得目标玩家列表，依次造成伤害（详见 [02_开局与流程.md](02_开局与流程.md) 怪物行动章节）。

## 三、使用卡牌

> 玩家在行动阶段可从手牌中使用卡牌，对应行动阶段行动选项「从手牌中打出 1 张牌」（详见 [02_开局与流程.md](02_开局与流程.md)）。

### 3.1 卡牌类型

玩家回合内可使用的卡牌共两种类型：**行动**与**装备**。拾荒卡与求生者游戏牌都属于其中一种。

| 类型 | 使用方式 | 使用后去向 |
|------|---------|-----------|
| 行动牌 | 即时使用，按卡牌文字执行效果 | 弃掉（按来源分派弃牌堆） |
| 装备牌 | 进入装备区，提供持续性技能效果 | 留在装备区 |

装填武器、吃食物、治疗玩家都属于行动牌，使用时都需要花费行动。

### 3.2 使用流程

从手牌中使用一张卡牌需花费 1 点行动次数。流程包含 4 个节点。

| 节点 | trigger 名 | 说明 |
|------|------------|------|
| 1 | 使用卡牌前（before_use_card） | **取消点**；可校验行动次数、手牌合法性 |
| 2 | 使用卡牌时（on_use_card） | **取消点**；装备牌/行动牌分流的最后拦截点 |
| 3 | 系统结算 | 扣 1 点行动次数（按 §3.4 延迟消耗机制处理）→ 按类型分流（装备/行动） |
| 4 | 使用卡牌后（after_use_card） | 整体触发一次 |

### 3.3 行动次数消耗

`use_card` 对装备牌和行动牌**统一消耗 1 点行动次数**。卡牌技能 content 内不再调用行动次数扣减方法，由使用卡牌流程统一负责。

### 3.4 延迟消耗机制（defer_action_cost）

行动牌技能若声明 `defer_action_cost = 是`（延迟消耗行动次数），使用卡牌流程的节点 3 不会立即扣减行动次数，而是延迟到该技能 content 执行时再扣减。

**取消回滚**：若延迟消耗的技能在 content 内调用事件取消方法，则牌退回手牌，不弃牌，不触发「使用卡牌后」节点。

非延迟消耗的行动牌与所有装备牌均在节点 3 立即扣减 1 点行动次数。

### 3.5 卡牌类型分流

- **装备牌** → 调用装备流程（详见 §3.6）将装备置入装备区；触发装备流程相关 trigger。
- **行动牌** → 按 §3.7 执行技能完整流程后弃掉这张牌。

### 3.6 装备流程

装备流程触发节点：卡牌进入装备区前（取消点）→ 卡牌进入装备区时 → 卡牌进入装备区后。

**系统预校验**（在「进入装备区前」之后、「进入装备区时」之前执行）：

1. **同名装备校验**：装备区中已有同名装备时，弃置旧的同名装备。
   - **燃料例外**：英文名为 `fuel` 的装备跳过同名校验，允许多张同时存在于装备区。
2. **装备栏容量校验**：新装备加入后若超出装备栏容量，玩家须从装备区选择弃置 1 张旧装备；若玩家取消选择，则装备失败、流程整体取消。

**实体化**：装备区持有的是装备实体（Equipment 类）而非来源卡。装备时通过 `card.instantiate(player)` 创建装备实体后置入装备区，并把装备技能挂载到玩家身上。装备区为空且来源卡非 EquipmentCard 时保底直接入区。

**装备卸下**：装备离开装备区有对外接口与内部接口：

- 对外接口触发卡牌离开装备区三节点 trigger（前/时/后，前节点为取消点）。
- 内部接口（`_unequip`）不触发任何 trigger，供弃置流程复用——弃置装备区装备时走内部卸下，避免触发离开装备区 trigger。

### 3.7 行动牌技能执行

行动牌可携带一个或多个技能。使用流程按以下顺序处理每个技能：

1. **可用条件校验**：调用技能的 filter 方法，target 以 null 求值；不通过则跳过该技能。
2. **目标选择**：根据技能的「目标选择」字段：
   - 整数 N（> 0）→ 玩家从合法目标中选择 N 个；玩家可取消（返回空列表则跳过该技能）。
   - −1 → 自动选取射程内全部合法目标（由 UI 层处理）。
3. **卡牌选择**：若技能声明「卡牌选择」N（> 0），玩家从手牌按「卡牌筛选」选择 N 张卡作为事件参数。
4. **效果执行**：调用技能的 content 方法。
   - 延迟消耗的技能在 content 内取消时按 §3.4 回滚。
5. **日志输出**：若有非自身目标，输出「玩家 对 目标 使用了 卡牌名」；否则输出「玩家 使用了 卡牌名」。

**弃牌**：所有技能执行完成后，**静默弃置**这张行动牌（不输出「弃置了」日志）。弃牌按来源（source 字段）自动分派到对应弃牌堆：

- source = scavenge（拾荒卡）→ 拾荒弃牌堆
- source = game（求生者游戏牌）→ 游戏牌弃牌堆

> 区分要点：拾荒卡使用后放入拾荒弃牌堆，**不要**放入求生者游戏牌弃牌堆。分派由弃牌流程内部按 source 字段自动处理（详见 [GameSystem/Entities/Player.md](../GameSystem/Entities/Player.md) 弃牌方法）。

### 3.8 手牌可用性判断

`is_card_usable(card)` 用于判断手牌当前是否可被使用（供 UI 确认按钮置灰）：

- **装备牌**：直接返回可使用（无 filter 门槛）。
- **行动牌**：至少存在一个「可用阶段 = 行动」的技能，且其可用条件通过（target 以 null 求值，时机与 `use_card` 的校验保持一致）；若该技能「目标选择」> 0，还须存在至少 1 个合法目标。

### 4.1 地图

| 术语 | 英文 | 定义与关键规则 |
|------|------|---------------|
| 地图块 | MapBlock | 游戏地图的基本单元。每个地块有名字、坐标、技能、怪物生成点数等属性。详见 [MapBlocksPack/MapBlocks.md](../Resource/MapBlocksPack/MapBlocks.md) |
| 地块坐标 | block coordinate | 地块在地图网格中的位置 `{ x, y }`。x = 列（横向），y = 行（纵向）。对应任务地图矩阵 `map[y][x]` |
| 相邻地块 | adjacent block | 上下左右四向相邻的地块（不含对角线）。移动、射程计算基于相邻关系 |
| 曼哈顿距离 | Manhattan distance | 两地块间的距离 `|x1 − x2| + |y1 − y2|`。用于射程判定（短/中/长距离） |
| 已展示 / 未展示 | revealed / unrevealed | 地图块的两种状态。玩家首次进入时翻开（展示），触发「展示地块时」效果 |
| 存活 / 已摧毁 | alive / destroyed | 地块状态。被大炸药等效果摧毁的地块变为「已摧毁」，从地图区域移除 |
| 怪物标记 | monster mark | 地块上的怪物标记，最多 3 个。标记 = 3 且有玩家时，玩家抓怪物卡而非加标记 |
| 目标标记 | objective mark | 任务特殊设置中的标记，挂载到地块上。玩家进入地块时触发标记效果（一次性）。可声明「初始怪物标记数」（预置怪物标记）与「移除条件」（怪物标记减少时检查，满足则自动移除） |
| 面包车 | van | 多数任务的出生点与游戏结束点。需添加足够燃料且所有存活玩家返回才能胜利 |
| 出生点 | spawn point | 玩家初始位置。任务地图配置中编号为 0 的地块 |
| 游戏结束点 | game end point | 部分任务的特殊结束地块（如军事基地）。任务地图配置中编号为 2 |
| 标记地块 | marked block | 任务地图配置中编号为 3 的地块，从地块池随机抽取 + 添加目标标记 + 按「初始怪物标记数」预置怪物标记 |
| 无地块 | no block | 任务地图配置中编号为 −1，表示该位置无地图块 |
| 地块池 | block pool | 地图构建时的地块候选池。从「任务地图块配置」按数量展开，「1」和「3」位置从中随机抽取 |
| 怪物生成点数 | monster spawn value | 地块属性之一。怪物出生检定时，投骰结果匹配的地块生成怪物 |
| 拾荒颜色 | scavenge color | 地块属性之一。该地块可拾荒的牌堆颜色集合（红/绿/蓝子集） |

### 4.2 玩家状态

| 术语 | 英文 | 定义与关键规则 |
|------|------|---------------|
| 生命值 | HP | 玩家当前生命值。≤ 0 时玩家死亡。详见 [02_开局与流程.md](02_开局与流程.md) 游戏结束章节 |
| 最大生命值 | max HP | 生命值上限。恢复生命值不超过此值 |
| 饥饿值 | hunger | 1–6。每回合 +1。达到 6 后翻面角色卡并叠加饥饿伤害标记 |
| 潜行值 | stealth | 用于潜行检定。潜行值 = 玩家潜行值 −（地块怪物数 + 怪物标记数） |
| 行动次数 | action count | 每回合 4 次。移动/抓牌/出牌/拾荒/执行卡牌行动各消耗 1 次 |
| 最大行动次数 | max action count | 行动次数上限。部分技能可临时增加 |
| 中毒标记 | poison mark | 标记。回合结算时受到等量伤害（无来源伤害） |
| 饥饿伤害等级 | hunger damage level | 角色卡翻面后的标记。等级 1–5 分别造成 2/4/6/8/致死伤害 |
| 角色卡牌 | character card | 玩家角色卡。饥饿值达 6 后翻面，减少饥饿值后恢复正面 |
| 装备区 | equipment zone | 装备牌所在区域。有容量限制（装备栏） |
| 手牌区 | hand | 手牌所在区域 |
| 怪物区 | monster zone | 玩家面前的怪物卡区域。怪物卡进入此区时与玩家纠缠 |
| 游戏牌堆 | game deck | 求生者游戏牌堆。抓牌从此处；牌堆空时玩家死亡 |
| 游戏牌弃牌堆 | game discard pile | 求生者游戏牌弃牌区域 |

| 触发目标标记时（on_objective_mark_triggered） | 玩家进入地块且触发未触发的目标标记后 | 移动流程 节点 11 | player | 否 |

> 注：摧毁地块类 trigger 由游戏级摧毁地块流程触发，对所有 player 按座位顺序触发。事件字段：source（摧毁者，可为空）、block（被摧毁的地块）。

### 4.7 特殊机制

#### 4.7.1 销毁 vs 弃置

| 机制 | 定义 | 进入区域 | 触发死亡流程 |
|------|------|---------|-------------|
| 销毁 | 将牌移出游戏 | 移出游戏（不进弃牌堆） | 否 |
| 弃置 | 将牌置入弃牌堆 | 对应弃牌堆 | 否 |
| 弃置怪物 | 弃置面前的一张非首领怪物并替换为怪物标记 | 怪物弃牌堆 + 加怪物标记 | **否**（纯移除，不触发「怪物死亡时」） |
| 击杀 | 通过伤害流程使生命值 ≤ 0 | 怪物弃牌堆 | **是**（触发「怪物死亡时」） |

#### 4.7.2 翻面

| 机制 | 定义 |
|------|------|
| 角色卡翻面 | 饥饿值达 6 后翻面角色卡，叠加饥饿伤害标记。减少饥饿值后恢复正面 |
| 地块翻面 | 部分地块技能涉及翻面效果（如隧道） |

#### 4.7.3 同生共死

| 机制 | 定义 |
|------|------|
| 同生共死 | 可选难度规则。开启后任何玩家死亡即所有求生者输掉游戏。由游戏级同生共死模式字段控制（默认关闭）。在玩家死亡流程末尾全灭判定之前检查：为真时立即触发游戏失败结束 |

#### 4.7.4 重调

| 机制 | 定义 |
|------|------|
| 重调 | 重新洗牌指定牌堆。详见 [SurvivorPacks/gunslinger.md](../Resource/SurvivorPacks/gunslinger.md) 快速拔枪 |

#### 4.7.5 移出游戏

| 机制 | 定义 |
|------|------|
| 移出游戏 | 将牌从游戏中移除。玩家死亡时所有求生者游戏牌移出游戏。区别于进入弃牌堆 |

#### 4.7.6 复合触发

| 机制 | 定义 |
|------|------|
| 复合触发 | 技能 trigger 字段支持「、」分隔的多个触发名。如「游戏开始时、受到伤害时」。技能 content 内可判断当前 trigger 分支执行不同效果。详见 [GameSystem/Core/EventSystem.md](../GameSystem/Core/EventSystem.md) |

#### 4.7.7 取消点

| 机制 | 定义 |
|------|------|
| 取消点 | 流程中可调用事件取消方法终止当前事件的节点。取消后流程立即终止，已执行的钩子不回滚（除移动流程会回滚地块技能）。各流程的取消点见 §4.6 各表「取消点」列 |

#### 4.7.8 游戏状态机

> 详见 [GameSystem/Core/GameStateMachine.md](../GameSystem/Core/GameStateMachine.md)。

| 术语 | 英文 | 定义与关键规则 |
|------|------|---------------|
| 游戏状态机 | game state machine | 独立类，由游戏对象持有。负责游戏级状态管理、回合队列管理、胜利/失败条件检查。不继承实体类（无技能、无 trigger） |
| 游戏阶段 | game phase | 状态机的状态字段，三值：等待（setup 之前）/ 游戏中 / 已结束。合法转换：等待 → 游戏中 → 已结束，其他转换非法 |
| 游戏结果 | game result | 胜利 / 失败 / 进行中（空）。「已结束」状态下访问 |
| 回合队列 | turn queue | 玩家队列，待执行的回合队列。队首为下一个行动玩家。标准情况下按座位顺序填充所有存活玩家；额外回合通过插入队首方法加入 |
| 跳过标记 | skip set | 玩家集合，需要跳过下个回合的玩家集合。跳过是一次性的，轮到时跳过并移除标记 |
| 额外回合 | extra turn | 通过插入队首方法加入的额外回合。当前玩家回合结束后立即执行。典型场景：部分技能效果让玩家获得额外回合 |
| 跳过回合 | skip turn | 通过标记方法让玩家跳过下个回合。轮到该玩家时跳过并移除标记。典型场景：怪物击晕等效果 |
| 当前回合玩家 | current player | 当前正在行动的玩家。等待 / 已结束状态下为空 |
| 委托模式 | delegation pattern | 游戏类的状态相关方法（开始游戏 / 游戏结束 / 获取当前玩家 / 下一回合）委托给状态机实现。游戏类仅保留全局区域与跨玩家操作 |
| 代理字段 | proxy field | 游戏类的游戏阶段 / 游戏结果 / 当前回合玩家字段通过代理访问状态机内部字段，向后兼容已有引用 |
| 胜利条件检查 | win condition check | 仅在玩家回合结束时检查：任务胜利条件 + 面包车燃料足够 + 所有存活玩家在面包车 + 面包车无怪物和怪物标记。若启动面包车所需燃料为空（−1 哨兵），跳过后 3 项面包车相关检查，仅依赖任务胜利条件 |
| 失败条件检查 | lose condition check | 即时检查，由各流程触发后直接调用游戏结束方法。失败条件：所有玩家死亡 / 怪物牌堆重洗后仍空 / 同生共死变体下任一玩家死亡 / 任务特定失败（如任务 8 潜行失败且无日记本） |

#### 4.7.9 任务系统

> 详见 [GameSystem/Game/Game.md](../GameSystem/Game/Game.md) 任务配置结构与 [GameSystem/Entities/Player.md](../GameSystem/Entities/Player.md) 任务系统方法。

| 术语 | 英文 | 定义与关键规则 |
|------|------|---------------|
| 任务配置 | mission config | 游戏对象字段，由任务包加载。含启动面包车所需燃料 / 检查胜利条件方法 / 任务状态三个字段 |
| 启动面包车所需燃料 | fuel required | 启动面包车所需的燃料值。整数或空：空（−1 哨兵）表示该任务不通过启动面包车胜利（如任务 4/8/9/11），此时胜利条件检查跳过面包车相关检查，仅依赖检查胜利条件方法 |
| 检查胜利条件 | check win condition | 任务包提供的函数。返回真表示任务特定胜利条件已满足。作为胜利条件检查的第一项条件 |
| 任务状态 | mission state | 字典，存储任务特定运行时状态。各任务自行约定键名，如任务 8 的「已记录科学家信息」「已解救科学家」「科学家装备牌」 |
| 任务物品 | mission item | 任务特定物品（如「满是灰尘的日记本」），作为普通拾荒卡存储在玩家手牌区，计入手牌上限。通过收集物品方法直接生成新卡加入手牌区（不消耗拾荒牌堆） |
| 持有物品查询 | has item | 搜索玩家手牌区 + 装备区判断是否持有指定物品 |
| 首领卡抽取 | draw boss card | 从怪物牌堆中筛选怪物级别 = 首领的卡抽取（牌堆没有则从怪物弃牌堆找）。抽取后复用抓取怪物卡完整流程，确保 trigger 正常触发 |
| 解救科学家 | rescue scientist | 让玩家选择是否花费 1 行动解救科学家。科学家作为装备牌装备到玩家面前（任务 8 特殊设置「把科学家拾荒卡放到一边」，预存储在任务状态） |
| 记录科学家信息 | record scientist info | 在任务状态中标记「已记录科学家信息」为真（任务 8 胜利条件之一：潜行失败但有日记本时记录信息） |
| 拾荒卡创建 | create scavenge card | 游戏级工厂方法，根据卡牌名从拾荒包定义克隆一张新卡（不消耗任何牌堆）。供收集物品方法调用 |
