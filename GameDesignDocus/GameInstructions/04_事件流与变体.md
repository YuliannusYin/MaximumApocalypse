## 一、事件触发机制

### 1.1 trigger 名索引（中英映射）

trigger 名在代码中以英文 snake_case 键名形式使用（`entity.gd` 的 `trigger()` / `trigger_only()` 调用、`skill.gd` 的 `matches_trigger()` 比对）。技能 JSON 的 `trigger` 字段支持「、」分隔的复合触发（如「受到伤害时、游戏开始时」），运行时按「、」拆分后逐项比对。

下表按流程类别归并 J 中分散定义的全部 trigger 名，**取消点**列标记为「是」的 trigger 允许技能在 content 内调用 `event.cancel()` 中断流程。

#### 1.1.1 伤害流程

| 中文译名 | 英文键名 | 取消点 | 触发对象 | 说明 |
| --- | --- | --- | --- | --- |
| 造成伤害前 | `before_deal_damage` | 否 | source | source 为 null 时跳过 |
| 受到伤害前 | `before_take_damage` | 否 | target | 始终触发（含无来源伤害） |
| 造成伤害时 | `on_deal_damage` | 否 | source | 可修改 `event.num`（伤害加成）；source 为 null 时跳过 |
| 受到伤害时 | `on_take_damage` | 是 | target | 可修改 `event.num`（伤害减免）或取消 |

### 1.2 trigger 执行流程

`Entity.trigger(trigger_name, event)` 是所有实体（Player / Monster / Card / MapBlock）触发事件的统一入口。其内部执行顺序如下：

1. **写入触发名**：调用 `EventSystem.set_trigger_name(event, trigger_name)`，将当前 trigger 名写入 `event.trigger_name`，供技能 filter / content 内查询当前所处节点。
2. **遍历技能副本**：对 `self.skills` 调用 `duplicate()` 取迭代副本。**取副本的目的是防止技能 content 在执行过程中挂载 / 移除技能导致迭代器失效**（如燃料 `on_draw_scavenge_card` 会调用 `equip` 挂载新技能，若不取副本则新挂载的同名触发器技能会在当前迭代中重复触发，可能死循环）。
3. **trigger 名匹配**：对副本中每个技能调用 `s.matches_trigger(trigger_name)`。`matches_trigger` 内部对技能 `trigger` 字段按「、」分隔拆分，逐一比对；为空或全部不匹配则跳过该技能。
4. **filter 验证**：调用 `s.execute_filter(self, event)`，签名实际为四参 `(player, target, event, Game) -> bool`（**非单参**，filter 函数体内可访问玩家、目标、事件、全局 Game）。返回 false 则跳过该技能。
5. **触发日志输出**：每技能执行 content 前输出「`{触发者名} 触发了 {技能名}`」日志（经 `LogColors.player` / `LogColors.skill_by_type` 染色）。触发者名按以下优先级解析：
   - 若 `self` 为 monster 且 `event` 含 `player` 字段：触发者取 `event.player`（怪物技能挂在玩家身上，但日志展示玩家名）
   - 若触发者为 player：取 `player_name`
   - 若触发者为 monster：取 `monster_name`
   - 若触发者为 map_block：取 `block_name`
   - 技能名优先取 `skill_name`，为空则取 `english_name`
6. **content 执行**：`await s.execute_content(self, event)`，签名实际为四参 `(player, target, event, Game) -> void`。技能 content 可读写 event 字段（如修改 `event.num`）或调用 `event.cancel()` 取消流程。
7. **cancel 中断**：content 执行后检查 `EventSystem.is_cancelled(event)`，若已取消则 `break` 跳出循环，后续技能不再执行。

> **关键约束**：所有 trigger 调用均为 `await`（异步），因为技能 content 可能包含异步操作（如玩家选择目标、检定投骰）。

### 1.3 trigger_only 限定触发

`Entity.trigger_only(trigger_name, event, skill_list)` 是 `trigger()` 的限定版本，仅在传入的 `skill_list` 中遍历匹配的技能，**不扫描 `self.skills` 全表**。

**与 `trigger()` 的差异**：

- `trigger()` 遍历 `self.skills` 全部技能
- `trigger_only()` 仅遍历调用方传入的 `skill_list` 子集

**执行流程**：除遍历范围外，其余步骤（写入触发名、trigger 名匹配、filter 验证、日志输出、content 执行、cancel 中断）与 `trigger()` 完全一致。

**典型用途**：抓取拾荒牌流程的 `on_draw_scavenge_card` trigger。当玩家抓取一张拾荒牌时，应仅触发该牌自身的强制技能（如「燃料：装备或弃掉」、「一无所获：弃掉」、「伏击！：抓怪物 + 弃掉」），而**不应触发玩家已装备卡牌上挂载的同名 `on_draw_scavenge_card` 技能**。`player.draw_scavenge()` 内部先收集当前被抓取牌的强制技能列表，再调用 `trigger_only` 限定触发。

## 二、event schema

### 2.1 通用字段

所有 event 均为 `Dictionary` 类型，由 `EventSystem.create_event(initial)` 工厂创建。通用字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `trigger_name` | String | 当前 trigger 名（如 `on_take_damage`），由 `Entity.trigger()` 在执行前写入 |
| `cancelled` | bool | 是否已取消，初始为 false；`cancel()` 调用后置 true |
| `cancel` | Callable | 取消闭包，调用 `event["cancel"].call()` 或 `EventSystem.cancel(event)` 后置 `cancelled = true` |

各流程专属字段在通用字段基础上追加，**字段名统一 snake_case**：`source_block` / `target_block` / `sneak_value` / `skip_judge` / `block` / `target` / `source` / `num` / `type` / `card` / `cards` / `targets` / `pile` / `mark` / `result` / `monster` / `target_players` / `player` / `equipment`。

> **注意**：`event` 是 `Dictionary`（引用类型），技能 content 内对 `event.num` 等字段的修改对后续节点可见。`cancel` 闭包通过 lambda 捕获 event 引用，调用后修改同一字典的 `cancelled` 字段。

---

### 2.2 各类 event schema

下表按 `event_system.gd` 的 `create_*_event` 工厂方法列示各类 event 的专属字段。所有 event 均包含 2.1 节的通用字段（`trigger_name` / `cancelled` / `cancel`），下表仅列专属字段。

#### 2.2.1 伤害 event

工厂：`create_damage_event(target, source, num, type, card)`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `target` | Entity | 受伤者（player 或 monster） |
| `source` | Entity | 伤害来源；null 表示无来源伤害（饥饿 / 中毒 / 地块摧毁），跳过所有 source 侧钩子 |

### 2.3 cancel 取消机制

event 的取消机制通过 `cancel` 字段（Callable 闭包）实现，**而非抛异常或返回值**。

**实现细节**（`event_system.gd::create_event`）：

- `cancel` 字段是一个 Callable，由 lambda 闭包工厂生成
- 闭包内捕获 event 字典引用（GDScript Dictionary 为引用类型，lambda 捕获的引用指向同一字典）
- 调用 `event["cancel"].call()` 后，闭包将 `event["cancelled"]` 置为 true

**调用方式**（两种等价）：

1. **直接调用闭包**：`event["cancel"].call()` —— 在技能 content 内直接调用
2. **静态包装**：`EventSystem.cancel(event)` —— 静态方法内部执行 `event["cancelled"] = true`

**中断行为**：

- `Entity.trigger()` / `trigger_only()` 在每个技能 content 执行后调用 `EventSystem.is_cancelled(event)` 检查
- 若已取消，立即 `break` 跳出技能迭代循环，**后续技能不再执行**
- 调用方（如 `Entity.damage()`）在 trigger 返回后再次检查 `is_cancelled`，若已取消则 `return` 中断整个流程

**取消点约束**：

- 仅 1.1 节标注「取消点：是」的 trigger 调用 `cancel()` 才有意义（如 `on_take_damage` / `before_enter_block` / `before_use_card` 等）
- 非 cancel 点 trigger 调用 `cancel()` 虽然语法允许，但调用方可能不检查 `is_cancelled`，行为未定义
- 死亡流程（`before_*_death` / `on_*_death` / `after_*_death`）明确不可取消
- 全局事件（`on_game_start` / `on_game_over`）不提供取消（`event.cancelled` 字段仍存在，但调用方不检查）

## 四、变体规则

### 4.1 变体字段

`VariantData`（`variant_data.gd`）是难度变体的静态数据类，从 `data/variants/*.json` 构造。字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | String | 变体唯一标识，如 `crisis` / `famine` / `shared_fate` |
| `english_name` | String | 英文名；JSON 未提供时默认取 `id` |
| `display_name` | String | 中文展示名 |
| `desc` | String | 变体描述（玩法影响说明） |

**数据加载**：`DataManager._load_variants()` 扫描 `res://data/variants/` 目录下所有 JSON 文件，逐个经 `_add_variant()` 构造为 `VariantData` 并缓存到 `_variants` 字典（键为 `id`）。

**查询接口**：

- `DataManager.get_variant(id) -> VariantData` —— 按 id 获取单个变体
- `DataManager.get_all_variants() -> Array` —— 获取所有变体列表

**消费场景**：`ui/room_state.gd` 在房间设置阶段调用 `DataManager.get_variant(key)` 读取已选变体，用于显示与启动应用。

### 4.2 三个变体详述

#### 4.2.1 危机四伏（crisis）

- **id**：`crisis`
- **英文名**：`crisis`
- **中文名**：危机四伏
- **描述**：往初始拾荒牌堆中添加更多的「伏击」。
- **玩法影响**：开局时向初始拾荒牌堆（红 / 绿 / 蓝 / 灰各色之一或全部，具体由房间设置决定）中追加额外的「伏击！」拾荒牌（gray 类）。玩家抓取拾荒牌时触发「伏击！」的 `on_draw_scavenge_card` 技能（经 `trigger_only` 限定触发），导致抓怪物卡 + 弃掉该拾荒牌，提升拾荒风险。

#### 4.2.2 大饥荒（famine）

- **id**：`famine`
- **英文名**：`famine`
- **中文名**：大饥荒
- **描述**：玩家随机投掷骰子来决定初始饥饿等级。
- **玩法影响**：游戏开始时（`on_game_start` 阶段或开局设置阶段），每位玩家投掷骰子，按骰子点数设置初始饥饿值（替代默认的 0 初始饥饿）。玩家饥饿值越高，饥饿结算阶段（`on_hunger_settlement`）受到的伤害越高，且潜行值相应降低（饥饿状态潜行值低于正常潜行值）。

#### 4.2.3 同生共死（shared_fate）

- **id**：`shared_fate`
- **英文名**：`shared_fate`
- **中文名**：同生共死
- **描述**：当任何玩家被消灭时，所有求生者输掉游戏。
- **玩法影响**：玩家死亡流程（`on_player_death` 或 `after_player_death` 节点）触发后，不再走原本的「全灭判定」（即所有玩家死亡才失败），而是**任一玩家死亡即立即触发 `game.game_over("lose")`**，结束游戏。此变体强化团队协作要求，单人冒进可能导致全队失败。

## 五、事件流程节点详表

> 本节保留 J 原文档的 21 个事件流程节点详表。trigger 名以代码英文键名为准（中英映射见 1.1）。`（系统结算）` / `（系统投骰）` 等标注为「—」的节点为非钩子节点，由系统直接执行不触发 trigger。

### 5.1 source 攻击 target 流程（伤害结算）

> **定义位置**：`Entity.damage()`
> **调用方法**：`target.damage(num, source, type="", card=null)`
> **取消点**：节点 4「受到伤害时」可调用 `event.cancel()`
> **特殊规则**：source 为 null 时跳过所有 source 侧钩子（节点 1 / 3 / 6），仅触发 target 侧
> **节点 5.5 / 5.6**：扣血后发射 EventBus 统计信号 + 输出受伤日志

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_deal_damage` | source | source 不为 null 时触发 |
| 2 | `before_take_damage` | target | 始终触发（含无来源伤害） |
| 3 | `on_deal_damage` | source | source 不为 null 时触发；可修改 `event.num`（伤害加成） |
| 4 | `on_take_damage` | target | **取消点**；可修改 `event.num`（伤害减免）或取消 |
| 5 | （系统扣血） | — | `target.reduce_hp(event.num)`，非钩子节点 |
| 5.5 | （统计信号） | — | 实际扣血量 > 0 时发射 `damage_taken`；source 不为 null 时同时发射 `damage_dealt`；非钩子节点 |
| 5.6 | （受伤日志） | — | 玩家 / 怪物受伤时按伤害类型（`monster_attack` / `hunger` / `poison` / `block_destroy`）输出对应日志；非钩子节点 |
| 6 | `after_deal_damage` | source | source 不为 null 时触发 |
| 7 | `after_take_damage` | target | 始终触发（含无来源伤害） |
| 8 | （死亡判定） | — | `target.get_hp() <= 0` → 调用 `target.death(source)`（多态：player_death 或 monster_death） |

### 5.2 玩家移动流程

> **定义位置**：`Player.move_to(target)`
> **取消点**：节点 5「进入地块前」可调用 `event.cancel()`，取消时回滚目标地块技能
> **核心原则**：所有地块技能挂载到玩家身上，由 `player.trigger()` 统一触发

| 节点 | trigger 名 | 说明 |
| --- | --- | --- |
| 1 | `before_leave_block` | 玩家离开当前地块前触发 |
| 2 | `on_leave_block` | 如森林：同回合内进入又离开 → 抓怪物 |
| 3 | `after_leave_block` | 离开完成 |
| 4 | （获取目标地块技能） | `player.获取地块技能(target)`，将目标地块技能挂载到玩家；非钩子节点 |
| 5 | `before_enter_block` | **取消点**；准入检定（如河流：潜行失败 → `event.cancel()`） |
| 6 | （移动时） | 坐标变更：`player.move_to_map_block(target)`；发射 `player_moved` 信号；非钩子节点 |
| 7 | （清理旧地块技能） | `source.清除技能(player)`，移动成功后才清理；非钩子节点 |
| 8 | `on_enter_block` | 一次性进入效果（军事基地造成伤害、监狱减行动、旷野抓怪物等） |
| 9 | `after_enter_block` | 展示未展示的地块（触发 `on_reveal_block`）；`player.trigger` |
| 10 | （潜行检定） | 目标地块有怪物标记时进行潜行检定，失败 → 移除标记并抓怪物；非钩子节点 |
| 11 | `on_objective_mark_triggered` | 玩家进入地块且触发未触发的目标标记后；每张未触发标记调用一次标记效果 |

**衍生 event**（节点 11）：`event.player` / `event.block` / `event.mark`（ObjectiveMark 结构）

### 5.3 玩家抓取怪物流程

> **定义位置**：`Player.draw_monster(n)`
> **取消点**：节点 1「抓取怪物卡前」可调用 `event.cancel()`（firefighter「梯子」在此取消跳过抓怪）
> **牌堆耗尽**：怪物牌堆空时重洗怪物弃牌堆；重洗后仍为空 → `game.game_over("lose")`
> **实体化**：每张怪物卡在节点 3-4 之间实体化（设置纠缠对象、初始化生命值）
> **递归调用**：节点 5 内 zombie 一大波僵尸（场上所有存活玩家各抓一张）、僵尸步行者会递归调用 `draw_monster`

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_draw_monster_card` | player | **取消点**；如 firefighter「梯子」取消跳过抓怪 |
| 2 | `on_draw_monster_card` | player | 每张触发；抓取动作执行 |
| 3 | `before_monster_enter_zone` | player | 每张触发；怪物卡实体化前 |
| 4 | `on_monster_enter_zone` | player 与 monster | 每张触发；player 与 monster 双侧触发；实体化后置入怪物区 |
| 5 | `after_monster_enter_zone` | player 与 monster | 每张触发；player 与 monster 双侧触发；如 zombie（一大波僵尸、僵尸步行者）、alien / robot / mutant 多处技能 |
| 6 | `after_draw_monster_card` | player | 整体触发一次；如 mechanic「感应地雷」对 `event.card` 造成伤害 |

> **注**：节点 2-5 每张怪物卡触发一次（逐张走完整流程后抓下一张）；节点 6 整体触发一次。

### 5.4 怪物死亡流程

> **定义位置**：`Monster.death(source)`
> **取消点**：无（死亡流程不可取消）
> **触发场景**：`Entity.damage()` 流程节点 8 中怪物生命值 ≤ 0

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 0 | （死亡日志 + EventBus） | — | 输出「X 被 Y 击杀」日志；发射 `monster_died` 信号；非钩子节点 |
| 1 | `before_monster_death` | monster | 死亡前最后时机 |
| 2 | `on_monster_death` | monster 与所有玩家怪物区其他存活怪物 | 触发怪物死亡事件；如 zombie（僵尸女王）、robot（爆破机器人、方阵机器人）；含跨怪物广播 |
| 3 | （清理） | — | 将怪物卡从纠缠玩家怪物区移除，置入怪物弃牌堆；非钩子节点 |
| 4 | `after_monster_death` | monster | 死亡完成 |

> **注意**：地图块 / 技能效果「弃置怪物」（如 hunter 迷彩服）为纯移除，不触发怪物死亡流程。

### 5.5 玩家死亡流程

> **定义位置**：`Player.death(source)`
> **取消点**：无（死亡流程不可取消）
> **触发场景**：`Entity.damage()` 流程节点 8 中玩家生命值 ≤ 0；或游戏牌堆无牌时摸牌

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 0 | （EventBus 信号） | — | 发射 `player_died` 信号；非钩子节点 |
| 1 | `before_player_death` | player | 死亡前最后时机 |
| 2 | `on_player_death` | player | 死亡事件触发 |
| 3 | （清理怪物区） | — | 怪物区怪物 → 弃牌堆，等量怪物标记（最多 3 个）放回地块；非钩子节点 |
| 4 | （清理游戏牌） | — | 所有求生者游戏牌移出游戏（手牌 + 装备 + 牌堆 + 弃牌堆）；非钩子节点 |
| 5 | （清理拾荒卡） | — | 拾荒卡按颜色洗回对应拾荒牌堆，各色分别洗牌；非钩子节点 |
| 6 | `after_player_death` | player | 死亡完成 |
| 7 | （全灭判定） | — | `game.all_players_dead()` 为真 → `game.game_over("lose")`；非钩子节点 |

### 5.6 使用卡牌流程

> **定义位置**：`Player.use_card(card)`
> **使用规则**：使用卡牌统一消耗 1 点行动次数（装备牌和行动牌均消耗）
> **取消点**：节点 1 / 2 均可调用 `event.cancel()`
> **卡牌分流**：装备牌 → 调用 `player.equip(card)` 进入装备区；行动牌 → 技能系统独立执行 content 后弃掉

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_use_card` | player | **取消点**；可校验行动次数、手牌合法性 |
| 2 | `on_use_card` | player | **取消点**；装备牌 / 行动牌分流的最后拦截点 |
| 3 | （系统结算） | — | 扣 1 点行动次数 → 按类型分流（装备 / 行动）；非钩子节点 |
| 4 | `after_use_card` | player | 整体触发一次 |

> **装备牌分流**：节点 3 中装备牌调用 `player.equip(card)`（见 5.7），装备栏容量校验失败时由 `equip()` 内部取消并提示。
> **行动牌分流**：节点 3 中行动牌的技能 content 由技能系统独立执行（use_card 不直接调用 `card.技能.content()`），执行后调用 `player.discard(card)` 弃掉（按 `card.source` 分派弃牌堆，见 5.16）。

### 5.7 装备进入装备区流程

> **定义位置**：`Player.equip(card)`
> **取消点**：节点 1 可调用 `event.cancel()`
> **系统预校验**（节点 1 之后、节点 2 之前，非钩子节点）：同名装备校验（弃置同名装备）+ 装备栏容量校验（玩家选择弃置装备直到能容下，无法容下则取消装备并提示）

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_equip` | player | **取消点** |
| — | （系统预校验） | — | 同名装备校验 + 装备栏容量校验；非钩子节点 |
| 2 | `on_equip` | player | 装备置入装备区 + 技能挂载；发射 `equipment_equipped` 信号 |
| 3 | `after_equip` | player | 装备进入完成 |

### 5.8 装备离开装备区流程

> **定义位置**：`Player.unequip(card)`
> **取消点**：节点 1 可调用 `event.cancel()`
> **调用场景**：`player.discard(card)` 检测到牌在装备区时先调用 `unequip`；装备流程中同名装备校验也通过 discard 调用 `unequip`

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_unequip` | player | **取消点** |
| 2 | `on_unequip` | player | 从装备区移除 + 技能移除；发射 `equipment_unequipped` 信号 |
| 3 | `after_unequip` | player | 装备离开完成 |

### 5.9 填充物消耗流程

> **定义位置**：`Player.consume_charge(equipment, num)`（equipment 为装备对象，需先通过 `player.get_equipment(name)` 获取）
> **取消点**：节点 1 / 2 可调用 `event.cancel()`
> **填充物不足**：`equipment.填充物当前量 < num` 时取消执行并提示（不扣减、不触发任何 trigger）
> **调用场景**：装备技能消耗弹药 / 燃料时调用（如手枪、打火机、摩托车、空尖弹特殊弹药等）

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_consume_charge` | player | **取消点** |
| 2 | `on_consume_charge` | player | **取消点**；可修改 `event.num` |
| 3 | （系统扣减） | — | `equipment.填充物当前量 -= event.num`；发射 `charge_consumed` 信号；非钩子节点 |
| 4 | `after_consume_charge` | player | 消耗完成 |
| 5 | `on_charge_depleted` | player | **衍生**：扣减后若 `填充物当前量 <= 0` 则触发；如 gunslinger 空尖弹 subSkill remove 在此弃置武器牌 |

### 5.10 玩家回合流程

> **规则定义**：玩家回合 21 节点流程，由 `GameStateMachine.next_turn()` 调用 `Player.start_turn()`
> **trigger 触发对象**：所有 trigger 均为 `player.trigger`（玩家身上的技能，含已挂载的地块技能）

| 节点 | trigger 名 | 说明 |
| --- | --- | --- |
| 1 | （进入玩家回合） | 非钩子节点。重置行动次数与回合临时标记，`in_phase = "turn_start"` |
| 2 | `before_turn_start` | 回合开始前触发 |
| 3 | `on_turn_start` | 回合开始；如 MapBlocks（避难所、电厂） |
| 4 | `before_monster_spawn` | 怪物出生检定前；`in_phase = "monster_spawn"` |
| 5 | `on_monster_spawn` | 进行怪物出生检定（见 5.14） |
| 6 | `before_draw_phase` | 摸牌前；`in_phase = "draw_phase"` |
| 7 | （摸牌阶段） | 从游戏牌堆抓 1 张牌；牌堆空 → 玩家死亡；非钩子节点 |
| 8 | `before_action_phase` | 行动阶段前；含潜行检定（地块有怪物标记时，检定在 trigger 之前执行）；`in_phase = "action"` |
| 9 | （行动阶段） | 执行 4 个行动 + 免费行动（制衡、交易）；非钩子节点 |
| 10 | `before_action_phase_end` | 行动阶段结束前；如 gunslinger（扣动扳机让我快乐 subSkill） |
| 11 | `on_action_phase_end` | 行动阶段结束 |
| 12 | `before_hunger_settlement` | 饥饿结算前；如 firefighter（野地夹克 subSkill）；`in_phase = "hunger_settlement"` |
| 13 | `on_hunger_settlement` | `player.increase_hunger(1)` |
| 14 | `before_poison_settlement` | 中毒结算前；`in_phase = "poison_settlement"` |
| 15 | `on_poison_settlement` | `player.poison()`（有中毒标记时） |
| 16 | `before_zone_monster_act` | 面前怪物行动前；`in_phase = "monster_act"` |
| 17 | `on_zone_monster_act` | 面前怪物按进入顺序行动（见 5.11） |
| 18 | `before_turn_end` | 回合结束前；如 gunslinger（扣动扳机让我快乐 subSkill）、MapBlocks（游乐园、警察局、城市街道）；`in_phase = "turn_end"` |
| 19 | `on_turn_end` | 回合结束；如 MapBlocks（游乐园） |
| 20 | （退出玩家回合） | 非钩子节点；`in_phase = "idle"` |
| 21 | （胜利判定） | 由 `GameStateMachine.check_win_condition()` 在 `start_turn()` 返回后执行，不在玩家流程内 |

> **死亡中断**：玩家可能在节点 7（牌堆空）、13（饥饿伤害致死）、15（中毒伤害致死）、17（怪物攻击致死）后死亡，死亡后立即 return，后续节点不再执行。

### 5.11 怪物行动流程

> **定义位置**：`Monster.act()`
> **触发场景**：玩家回合节点 17「面前怪物行动时」；按怪物卡进入怪物区的先后顺序行动
> **击晕**：被灭火器击晕的怪物跳过本次行动，击晕仅持续到下次行动

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_monster_act` | monster | 单个怪物行动前 |
| 2 | `on_monster_act` | monster | 怪物开始行动 |
| 3 | `before_monster_attack` | monster | 攻击前 |
| 4 | `on_monster_attack` | monster | 根据射程对目标发动攻击；如 alien（外星收割者、外星指挥官、外星入侵者、外星飞船）、mutant（狂暴的突变体、突变体老鼠） |
| 5 | `after_monster_attack` | monster | 攻击后；如 zombie（僵尸潜行者） |
| 6 | `after_monster_act` | monster | 单个怪物行动结束 |

> **注**：「怪物行动前 / 时 / 后」（`before_monster_act` / `on_monster_act` / `after_monster_act`）与玩家回合流程中的「面前怪物行动前 / 时」（`before_zone_monster_act` / `on_zone_monster_act`）是不同层级的 trigger。前者是单个怪物级别的 trigger，后者是玩家回合阶段级别的 trigger。

### 5.12 抓取拾荒牌流程

> **定义位置**：`Player.draw_scavenge(n, pile)`
> **取消点**：节点 1「抓取拾荒牌前」可调用 `event.cancel()`（手电筒在此取消并替代为「看 2 留 1 放 1」）
> **牌堆耗尽**：牌堆为空时停止抓取（不重洗弃牌堆）

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_draw_scavenge_card` | player | **取消点**；如 blue（手电筒）取消并替代为「看 2 留 1 放 1」 |
| 2 | （逐张抓取） | — | 抓 1 张 → 入手牌区 → 触发「时」→ 抓下一张；牌堆空则停止；非钩子节点 |
| 3 | `on_draw_scavenge_card` | player | 每张牌触发一次；**经 `trigger_only` 限定仅触发当前被抓取牌自身的强制技能**；如 red（燃料：装备或弃掉）、gray（一无所获：弃掉；伏击！：draw_monster + 弃掉）；发射 `scavenge_drawn` 信号 |
| 4 | `after_draw_scavenge_card` | player | 所有牌抓取完成 |

> **注**：pile 参数统一为 pile 对象（颜色字符串通过 `game.get_scavenge_pile(颜色)` 转换）。手牌上限由上层校验。

### 5.13 潜行检定流程

> **定义位置**：`Player.sneak_judge()`
> **触发场景**：玩家进入有怪物标记的地块时（5.2 节点 10）；玩家回合行动阶段前（地块有怪物标记时）
> **检定公式**：潜行值 = 玩家潜行值 - (地块怪物数 + 怪物标记数)；检定结果 ≤ 潜行值则成功
> **`event.result` 结构**：`{ value: 骰子点数, success: 布尔值 }`

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_sneak_judge` | player | 技能可设置 `skip_judge=true` + `result={...}` 跳过投骰；如 robot（激光无人机）、firefighter（猎犬，河流地块自动通过）；发射 `sneak_judge_triggered` 信号 |
| 2 | （系统投骰） | — | 若未跳过：投骰并计算 result；若跳过：使用技能指定的 result；非钩子节点 |
| 3 | `on_sneak_judge` | player | 技能可修改 `event.result`；如 gray（科学家，设为失败） |
| 4 | `after_sneak_judge` | player | 非取消点；可查询 `event.result` |

> **失败处理**：由调用方负责（如 `move_to` 节点 10：移除所有怪物标记，每移除一个抓一张怪物卡）。`sneak_judge()` 返回 `event.result.success`。

### 5.14 怪物出生检定流程

> **定义位置**：`Player.monster_spawn_judge()`
> **触发场景**：玩家回合节点 5「怪物出生时」（`on_monster_spawn`）
> **检定规则**：投两颗大骰子，匹配已展示地块的 `monster_spawn_value`
> **`event.result` 结构**：`{ value: 骰子点数, success: 布尔值 }`（success 无意义，恒为 true）

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_spawn_judge` | player | 技能可设置 `skip_judge=true` + `result={...}` 跳过投骰 |
| 2 | （系统投骰） | — | 若未跳过：投骰并计算 result；若跳过：使用技能指定的 result；非钩子节点 |
| 3 | `on_spawn_judge` | player | 技能可修改 `event.result` |
| 4 | `after_spawn_judge` | player | 非取消点；可查询 `event.result` |
| 5 | （结果处理） | — | 匹配地块：标记 < 3 → +1 标记；标记 = 3 且有玩家 → 每位玩家抓 1 怪物；非钩子节点 |

> **注**：玩家回合流程中的 `before_monster_spawn` / `on_monster_spawn`（5.10 节点 4-5）是玩家回合阶段级别的 trigger，与此处的检定流程 trigger（`before_spawn_judge` / `on_spawn_judge`）不同层级。

### 5.15 抓取游戏牌流程

> **定义位置**：`Player.draw(n)`
> **取消点**：节点 1「抓取游戏牌前」、节点 2「抓取游戏牌时」均可调用 `event.cancel()`
> **死亡规则**：逐张抓取，每张抓取前检查牌堆；牌堆为空时尝试抓取 → 调用 `player.player_death(null)` 并 return（跳过节点 4）

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_draw_game_card` | player | **取消点**；可取消本次抓牌 |
| 2 | `on_draw_game_card` | player | **取消点**；可修改 `event.num`（如技能加摸 1 张）或取消 |
| 3 | （逐张抓取） | — | 每张抓取前检查牌堆，牌堆为空 → `player_death(null)` 并 return；否则从游戏牌堆抓 1 张到手牌区；发射 `card_drawn` 信号；非钩子节点 |
| 4 | `after_draw_game_card` | player | 所有牌抓取完成；可访问 `event.cards` |

> **注**：手牌上限（10 张）由上层校验，`draw()` 不处理。牌堆不足 n 张时逐张抓取，抓到剩余牌后下一次尝试抓取时触发死亡。

### 5.16 弃置牌流程

> **定义位置**：`Player.discard(target, position=null, quantity=1, type=null)`
> **取消点**：节点 1「弃置牌前」可调用 `event.cancel()`
> **重载签名**：target 支持 card 对象 / cards 列表 / name 字符串 / type 字符串（type 参数非空时按 `card.类型` 弃置）
> **弃牌堆分派**：按卡牌 source 自动分派（scavenge → 对应颜色拾荒弃牌堆，game → 游戏牌弃牌堆）

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_discard` | player | **取消点**；可取消本次弃牌 |
| 2 | `on_discard` | player | 每张触发；从原位置移除 → 进入对应弃牌堆 → 触发；发射 `card_discarded` 信号 |
| 3 | `after_discard` | player | 整体触发一次 |

> **注**：多张弃置时逐张触发「弃置牌时」（与 `draw_scavenge` / `draw_monster` 模式对齐）。position 为 null 时搜索所有区域（手牌区 + 装备区）。

### 5.17 销毁牌流程

> **定义位置**：`Player.remove_card(target, position=null, quantity=1)`
> **取消点**：节点 1「销毁牌前」可调用 `event.cancel()`
> **与弃置的区别**：销毁的牌不进入弃牌堆，而是移出游戏（调用 `game.remove_card(card)`）

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_remove_card` | player | **取消点**；可取消本次销毁 |
| 2 | `on_remove_card` | player | 每张触发；从原位置移除 → 移出游戏 → 触发 |
| 3 | `after_remove_card` | player | 整体触发一次 |

> **注**：多张销毁时逐张触发「销毁牌时」。重载签名支持 card 对象 / cards 列表 / name + position + quantity。

### 5.18 回复生命值流程

> **定义位置**：`Player.recover(num)`
> **取消点**：无（参考术语表中「回复生命时」标记为「否」）
> **数值约束**：节点 3 系统加血时受最大生命值上限约束（`min(event.num, player.get_max_hp() - player.get_hp())`）

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_recover` | player | 回复前触发 |
| 2 | `on_recover` | player | 可修改 `event.num`（如 surgeon 手术刀·回复、手套：`event.num += 1`） |
| 3 | （系统加血） | — | `player.add_hp(min(event.num, player.get_max_hp() - player.get_hp()))`，受最大值约束；发射 `hp_recovered` 与 `healing_done` 信号；非钩子节点 |
| 4 | `after_recover` | player | 回复完成后触发 |

> **注**：节点 2 为 surgeon 手术刀·回复、手套使用的 trigger（forced 为 true 强制发动并修改 `event.num`）；节点 1 / 4 按命名模式对称包围系统加血节点，目前无具体技能引用，保留为通用 trigger。
> **与伤害流程的差异**：无 source 侧（回复无来源概念）；无取消点，但保留 `event.cancel()` 接口以备未来扩展。
> **与 `player.add_hp(n)` 的区别**：`add_hp` 为底层原子方法，直接修改生命值数值，不触发钩子且不受最大值约束；`recover` 走完整 4 节点流程。

### 5.19 游戏开始流程

> **定义位置**：`GameStateMachine.start_game()`（Game 类委托调用）
> **调用方法**：`game.start_game()` → `状态机.start_game()`
> **前置条件**：游戏初始化完成；状态为 `WAITING`
> **取消点**：无（全局事件，不提供取消）
> **trigger 触发对象**：所有 player（按座位顺序依次触发）。Game 类不继承 Entity，无自身 trigger。

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 0 | （EventBus 信号） | — | 发射 `game_started` 信号；重置统计追踪器并启动计时器；非钩子节点 |
| 1 | （抓初始手牌） | — | 每个玩家抓 4 张牌；非钩子节点 |
| 2 | （抓初始怪物卡） | — | 每个玩家抓 1 张怪物卡；非钩子节点 |
| 3 | `on_game_start` | player | 按座位顺序对所有 player 触发；典型场景：gunslinger「快速拔枪」从牌堆中装备【柯尔特手枪】 |
| 4 | （第零轮重调） | — | `_round_zero()`：每个存活玩家依次进行特殊重调回合，可选择返回全部手牌并重新抓取等量牌，支持多次重调；此回合不执行 21 节点流程、不增加饥饿值、不被怪物攻击；非钩子节点 |
| 5 | （进入第一回合） | — | `next_turn()`，开始第一玩家回合；非钩子节点 |

> **event schema**：`event.player`、`event.cancelled`（无 `cancel()` 调用，全局事件不取消）
> **重要偏差**：`game_state_machine.gd` 实际未调用 `EventSystem.create_game_start_event(player)`，而是直接使用 `EventSystem.create_event({"player": player})` 构造等价 event。
> **复合触发**：技能 trigger 字段支持复合触发，如「游戏开始时、受到伤害时」。content 内可通过查询当前触发名（`event.trigger_name` 字段）判断当前实际触发的 trigger，走不同分支。

### 5.20 游戏结束流程

> **定义位置**：`GameStateMachine.game_over(result)`（Game 类委托调用）
> **调用方法**：`game.game_over(result)` → `状态机.game_over(result)`（result 为 `GameResult.WIN` / `GameResult.LOSE` 枚举）
> **触发场景**：所有玩家死亡（lose）；或胜利条件达成（win）；或怪物牌堆重洗后仍空（lose）
> **取消点**：无（游戏结束不可逆）
> **trigger 触发对象**：所有 player（按座位顺序依次触发）
> **状态转换**：可从 `PLAYING` 或 `WAITING` 状态调用（`WAITING` 时直接强制进入 `GAME_OVER`，用于测试 / 异常场景）

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | （设置状态） | — | `current_state = GameState.GAME_OVER`；`game_result = result`；停止统计计时器；记录 `last_player`；清空回合队列；非钩子节点 |
| 2 | （日志输出） | — | `WIN` → 「求生者成功逃离启示录的废土！」；`LOSE` → 「所有求生者死亡，游戏失败。」；非钩子节点 |
| 3 | `on_game_over` | player | 按座位顺序对所有 player 触发；`event.result` 携带胜负枚举值 |
| 4 | （EventBus 信号） | — | 发射 `game_over` 信号；标记 `game_over_called = true`；非钩子节点 |

> **event schema**：`event.player`、`event.result`（`GameResult.WIN` / `GameResult.LOSE`）、`event.cancelled`（无 `cancel()` 调用，游戏结束不可逆）
> **重要偏差**：`game_state_machine.gd` 实际未调用 `EventSystem.create_game_over_event(player, result)`，而是直接使用 `EventSystem.create_event({"player": player, "result": result})` 构造等价 event。
> **注**：当前无技能使用「游戏结束时」trigger，作为对称设计与未来扩展点保留。技能可按 `event.result` 分支处理胜负场景。

### 5.21 摧毁地块流程

> **定义位置**：`Game.destroy_map_block(block, source)`
> **调用方法**：`game.destroy_map_block(block, source)`（source 可为 null，如无来源效果摧毁地块）
> **取消点**：节点 1「摧毁地块前」可调用 `event.cancel()`（取消后地块不被摧毁，已触发的前置钩子不回滚）
> **trigger 触发对象**：所有 player（按座位顺序依次触发，Game 类不继承 Entity，通过遍历 `game.players` 调用 `player.trigger()` 实现）
> **核心原则**：地块摧毁是非可逆事件；流程顺序为「前取消点 → 玩家弹出 → 怪物标记消灭 → 时节点 → 状态变更 → 后节点」

| 节点 | trigger 名 | 触发对象 | 说明 |
| --- | --- | --- | --- |
| 1 | `before_destroy_block` | 所有 player | **取消点**；如任务特殊规则可在此阻止关键地块被摧毁；source 为 null 时也触发 |
| 2 | （玩家弹出） | — | 处理地块上的玩家：有相邻存活地块 → 玩家选择 `target = player.choose_map_block(adjacent_blocks)` 后弹出；无相邻存活地块 → `player.damage(5, null, "block_destroy")`。弹出**不触发完整移动钩子**（非主动移动），仅清理旧地块技能、设置坐标、获取新地块技能（若新地块未展示则展示并触发效果）；非钩子节点 |
| 3 | （怪物标记消灭） | — | `block.怪物标记数 = 0`，地块上的怪物标记全部消灭（不触发怪物死亡流程，纯标记清理）；非钩子节点 |
| 4 | `on_destroy_block` | 所有 player | 系统结算点；此时玩家已弹出、怪物标记已消灭，但地块状态仍为「存活」。可在此读取地块信息做最后处理 |
| 5 | （状态变更） | — | `block.地块状态 = "已摧毁"`；`game.地图区域.remove(block)`，地块从地图区域移除；非钩子节点 |
| 6 | `after_destroy_block` | 所有 player | 地块摧毁完成；典型用途：检查任务胜利条件（如任务 12 检查 3 个标记地块是否全部被摧毁） |

> **玩家弹出规则细节**（节点 2）：
> - 弹出**不调用** `player.move_to(target)`，避免触发完整的离开 / 进入地块钩子（防止重复触发地块技能、潜行检定等）
> - 弹出流程：
>   1. `block.清除技能(player)` —— 清理被摧毁地块上的技能
>   2. `player.move_to_map_block(target)` —— 仅更新坐标
>   3. `target.获取地块技能(player)` —— 挂载新地块技能
>   4. 若 `!target.is_revealed()` → `target.reveal(player)` —— 展示新地块并触发展示效果
> - 若相邻存活地块为空，玩家受到 5 点无来源伤害（`player.damage(5, null, "block_destroy")`）

> **典型应用**：
