# 开局与流程

## 一、开局设置

### 1.1 游戏房间

玩家点击"开始游戏"按钮进入游戏房间界面，房主为创建游戏房间的玩家。游戏房间界面分三栏：

- **游戏设置（左栏）**：房主选择要进行的任务或"随机任务"，并可进行额外设置（如是否开启变体等）。
- **任务详情（中栏）**：根据房主选择的任务加载详情，包含任务名、任务难度、任务介绍等，最下为"开始游戏"按钮。任务详情格式见 `Resource/MissionPacks/basic-mission_1.md`。
- **玩家设置（右栏）**：房主添加或删除游戏座位（最少 1 个、最多 4 个，每个座位对应一名求生者），邀请玩家进入房间，并为每个座位分配玩家或 AI 玩家（如座位 1 玩家 1、座位 2 AI）。座位上的玩家选择自己要扮演的求生者（如座位 1 选消防员、座位 2 选枪手）。所有座位都设置好后才能开始游戏。

设置完游戏房间后，点击"开始游戏"按钮开始加载进入游戏。

### 1.2 游戏初始化

1. 加载本局游戏的所有求生者角色卡、立像和求生者游戏牌堆。
2. 根据任务加载本局游戏的所有怪物卡，洗混组成怪物牌堆。
3. 根据任务说明构建三个不同的拾荒牌堆（蓝、绿、红），分别洗乱。
4. 根据任务说明构建地图：依据任务包的「任务地图布局」二维数组和「任务地图块配置」构建实际地图。构建逻辑（模板加指定加随机）：
    - 无地块（图例 -1）：跳过该位置。
    - 出生点（图例 0）：使用任务包指定的地块名实例化（如"购物中心"）。
    - 未知随机地块（图例 1）：从「任务地图块配置」地块池中随机抽取一个实例化。
    - 游戏结束点（图例 2）：使用任务包指定的地块名实例化（如"面包车"）。
    - 标记地块（图例 3 等）：从地块池随机抽取一个实例化，并添加任务定义的目标标记。
    每个地块实例化后设置坐标，添加到地图区域。
5. 根据任务说明将玩家立像放到地图中的出生点（编号 0 的地块）上。
6. 初始化游戏区域：
    - **全局区域**：
        - A. 怪物牌堆（怪物牌堆空时把怪物弃牌堆重新洗成新的牌堆）
        - B. 怪物弃牌堆
        - C. 三色拾荒牌堆（拾荒牌堆空时不会重洗拾荒弃牌堆）
        - D. 拾荒弃牌堆（不分颜色，所有颜色的拾荒牌弃置后都进入此弃牌堆）
        - E. 地图区域
        - F. 卡牌结算区
        - G. 所有玩家的区域
    - **单个玩家区域**：
        - A. 求生者角色卡（用于表示玩家的状态，如饥饿值、生命值等）
        - B. 求生者手牌区
        - C. 求生者装备区
        - D. 求生者怪物区（纠缠玩家的怪物卡所在区域，又称"玩家面前的怪物"；纠缠玩家的怪物与玩家在同一个地图块内）
        - E. 求生者游戏牌堆（牌堆空时不会重新洗游戏牌弃牌堆）
        - F. 求生者游戏牌弃牌堆

### 1.3 游戏开局与抓取怪物卡

游戏初始化完成后，正式进入开局流程（完整时序详见本章第二节"游戏开始"流程）。开局包含：

1. 每名玩家从对应的求生者游戏牌堆抓 4 张牌作为初始手牌（每名玩家的手牌上限为 10）。
2. 每名玩家抓取 1 张怪物卡，放到自己的角色面前。每个纠缠玩家的怪物卡会停留在玩家的角色面前（即使玩家移动了），直到被消灭或者通过其它卡牌的效果被赶走。玩家可以攻击其它玩家面前的怪物，只要该怪物在该玩家的攻击范围内。
3. 对每名玩家触发"游戏开始时"事件。
4. 进入第零轮重调阶段（详见 2.3 节）。
5. 进入第一玩家回合，按游戏房间的座位次序依次进行回合。

> **规则更新点**：原"每名玩家可进行一次重调"已合并扩展为"第零轮重调阶段"，支持多次重调，详见 2.3 节。

每张怪物卡在进入玩家的求生者怪物区时进行实体化，实体化后的怪物具备以下属性：

- 怪物纠缠对象（一个怪物卡在同一时刻只能纠缠一个玩家）
- 怪物类型
- 怪物最大生命值
- 怪物当前生命值
- 怪物伤害值
- 怪物射程
- 怪物技能

> 怪物卡抓取流程（7 节点）与怪物卡实体化细节见 `GameSystem/Entities/Player.md` 与 `GameSystem/Entities/Monster.md`。

## 二、游戏状态机

游戏状态机由游戏全局对象持有，独立于实体类（不继承实体，无技能、无触发）。职责包括游戏级状态管理、回合队列管理、胜利与失败条件检查。

### 2.1 状态枚举

游戏状态（GameState）采用整型枚举，包含三个值：

| 枚举值 | 含义 |
|------|------|
| 等待（WAITING） | 游戏初始化完成但尚未开始；游戏开局前的等待状态 |
| 进行中（PLAYING） | 游戏正在进行，玩家按回合队列轮流行动 |
| 游戏结束（GAME_OVER） | 游戏已结束（胜利或失败） |

游戏结果（GameResult）枚举包含胜利（WIN）与失败（LOSE）两个值；游戏结束字段（game_result）初值为 -1 表示未结束。

> **关于首成员为 WAITING 而非 SETUP 的命名**：状态机初始状态在初始化中被显式置为等待（WAITING），同时游戏结束流程允许从等待状态强制进入游戏结束（详见 2.5 节），用于测试或异常场景的快速结算。因此首成员未命名为"设置"（SETUP），而以"等待"涵盖初始化完成后的所有非进行中状态。

### 2.2 状态转换

状态转换函数（transition_to）对状态变化进行合法性校验，仅允许以下两条转换路径：

- 等待 → 进行中
- 进行中 → 游戏结束

非法转换时打印错误日志并直接返回，**不抛出异常**。

> 例外：游戏结束流程允许在等待状态下直接将状态赋值为游戏结束，绕过状态转换函数，详见 2.5 节。

### 2.3 第零轮重调

第零轮重调阶段（`_round_zero`）发生在游戏开始流程中、第一玩家回合之前，是一项规则更新点：原"每名玩家可进行一次重调"的描述已合并扩展为"第零轮重调阶段"。该阶段不执行玩家回合 21 节点流程，不增加饥饿值、不被怪物攻击。

流程：

1. 日志输出"第 0 轮（重调阶段）"。
2. 按存活玩家依次进行重调回合：
    - 设置当前回合玩家，将玩家的当前阶段（in_phase）置为第零轮（round_zero）。
    - 循环等待玩家的重调决策（**支持多次重调**，直到取消或超时）：
        - 玩家选择"确定"：将全部手牌洗回求生者游戏牌堆，重新洗牌，抓取与刚才弃回等量的牌。
        - 玩家选择"取消"：退出循环。
    - 重调回合结束后将当前阶段置为空闲（idle）。
3. 全部玩家重调完毕后清空当前回合玩家。

### 2.4 回合队列

回合队列（turn_queue）由状态机维护，队首为下一个行动玩家，包含标准回合与额外回合。

| 操作 | 含义 |
|------|------|
| 进入下一回合（next_turn） | 从队列中取出队首玩家并执行其回合；若队列空则填充新一轮 |
| 加入额外回合（queue_extra_turn） | 将指定玩家插入队列队首，使其获得一个额外回合；仅在游戏进行中有效，且玩家须存活 |
| 跳过下回合（skip_next_turn） | 标记玩家下个回合被跳过；跳过是一次性的，执行后移除 |
| 跳过标记（skip_turn_marks） | 字典结构，键为玩家，值为是否跳过 |

回合队列填充与跳过逻辑：

- 队列空时调用填充新轮（`_fill_new_turn_queue`）：当前轮数（turn_number）自增 1，按座位顺序将所有存活玩家加入队列，日志输出"第 N 轮"。
- 取队首时跳过已死亡玩家与被跳过标记的玩家；若队列空且仍有存活玩家，则填充新一轮；若无存活玩家则返回空，触发游戏失败结算。

### 2.5 游戏开始与结束

**游戏开始（start_game）** 流程依次执行：

1. 状态从等待转换为进行中。
2. 发射游戏开始信号；启动统计追踪器（重置玩家统计、开始计时）。
3. 每名玩家抓 4 张初始手牌。
4. 每名玩家抓 1 张初始怪物卡。
5. 对每名玩家触发"游戏开始时"事件（on_game_start）。
6. 进入第零轮重调阶段（详见 2.3 节）。
7. 进入第一玩家回合。

**游戏结束（game_over）** 流程：

- **允许从进行中或等待状态调用**：若当前状态为等待，直接将状态赋值为游戏结束（绕过状态转换函数），用于测试或异常场景；若当前状态已为游戏结束则直接返回。
- 设置游戏结果（胜利或失败），停止统计计时器。
- 将当前回合玩家保存到"最后回合玩家"字段（last_player），供结算场景高亮使用；清空当前回合玩家与回合队列。
- 输出胜负日志（胜利："求生者成功逃离启示录的废土！"；失败："所有求生者死亡，游戏失败。"）。
- 对每名玩家触发"游戏结束时"事件（on_game_over）。
- 设置游戏对象的"已调用游戏结束"标记与游戏结果字符串，并发射游戏结束信号。

## 三、玩家回合流程（21 节点）

每名玩家按座位顺序轮流进行回合，直到游戏结束。回合切换由状态机的"进入下一回合"流程驱动；额外回合与跳过回合由状态机回合队列管理（详见 2.4 节）。

```
游戏开局 → 座位 1 玩家回合 → 座位 2 玩家回合 → 座位 3 玩家回合 → 座位 4 玩家回合
       ↑                                                                     │
       └─────────────────────────────────────────────────────────────────────┘
                                  （循环直至游戏结束）
```

玩家回合完整流程共 21 个节点，含 7 个非钩子节点（节点 1 / 7 / 9 / 20 / 21）和 14 个钩子节点。玩家在摸牌、饥饿结算、中毒结算、面前怪物行动后均可能死亡，死亡后流程中止。

阶段字段（in_phase）的英文值与中文显示名映射：

| 阶段英文名 | 中文显示名 |
|----------|----------|
| turn_start | 回合开始 |
| monster_spawn | 怪物出生 |
| draw | 摸牌阶段 |
| action | 行动阶段 |
| hunger | 饥饿结算 |
| poison | 中毒结算 |
| monster_action | 怪物行动 |
| turn_end | 回合结束 |
| idle | 回合外 |
| round_zero | 第零轮 |

21 节点流程：

| # | 节点 | 阶段 | 系统行为与说明 |
|---|------|------|---------------|
| 1 | （进入玩家回合） | 回合开始 | 非钩子节点。重置行动次数为最大行动次数（max_action_count），清除回合临时标记（如"避难所失效"等持续到回合结束的标记），重置主动技能使用次数 |
| 2 | 回合开始前 | 回合开始 | 钩子节点 |
| 3 | 回合开始时 | 回合开始 | 钩子节点（如地块避难所、电厂等） |
| 4 | 怪物出生前 | 怪物出生 | 钩子节点 |
| 5 | 怪物出生时 | 怪物出生 | 钩子节点，并进行一次怪物出生检定（详见 `03_判定与术语.md`） |
| 6 | 摸牌阶段前 | 摸牌阶段 | 钩子节点 |
| 7 | （摸牌阶段） | 摸牌阶段 | 非钩子节点。从求生者游戏牌堆抓 1 张牌。**牌堆空不能抓牌时玩家死亡，流程中止** |
| 8 | 行动阶段前 | 行动阶段 | 钩子节点。**若玩家所在地块有怪物标记，先进行潜行检定**：检定在钩子触发之前执行，失败时移除该地块所有怪物标记，每移除一个抓一张怪物卡。钩子触发时地块已无怪物标记 |
| 9 | （行动阶段） | 行动阶段 | 非钩子节点。执行 4 个行动加免费行动（详见下方"行动阶段"）。行动次数耗尽或玩家主动结束时进入下一节点 |
| 10 | 行动阶段结束前 | 行动阶段 | 钩子节点（如枪手"扣动扳机让我快乐"子技能） |
| 11 | 行动阶段结束时 | 行动阶段 | 钩子节点 |
| 12 | 求生者饥饿状态结算前 | 饥饿结算 | 钩子节点（如消防员"野地夹克"子技能） |
| 13 | 求生者饥饿状态结算时 | 饥饿结算 | 钩子节点，并增加 1 点饥饿值。**饥饿伤害致死时玩家死亡，流程中止** |
| 14 | 求生者中毒状态结算前 | 中毒结算 | 钩子节点 |
| 15 | 求生者中毒状态结算时 | 中毒结算 | 钩子节点，并执行中毒结算（玩家有中毒标记时受到等量伤害）。**中毒致死时玩家死亡，流程中止** |
| 16 | 面前怪物行动前 | 怪物行动 | 钩子节点 |
| 17 | 面前怪物行动时 | 怪物行动 | 钩子节点，玩家面前的怪物按进入求生者怪物区的顺序行动（先进入先行动），详见本章第四节"怪物行动"。**怪物攻击致死时玩家死亡，流程中止** |
| 18 | 回合结束前 | 回合结束 | 钩子节点（如枪手"扣动扳机让我快乐"子技能、地块游乐园 / 警察局 / 城市街道等） |
| 19 | 回合结束时 | 回合结束 | 钩子节点（如地块游乐园） |
| 20 | （退出玩家回合） | 回合外 | 非钩子节点。重置阶段为回合外 |
| 21 | （胜利判定） | — | 非钩子节点。由状态机的胜利条件检查流程在玩家回合返回后执行。**注意：胜利条件只在玩家回合结束时检查，玩家依然会在回合结束前受到伤害** |

> **死亡中断**：节点 7 / 13 / 15 / 17 后均检查玩家是否存活，死亡则立即中止后续节点。玩家死亡流程由抓牌 / 增加饥饿 / 中毒 / 怪物攻击流程内部触发，详见本章第五节。
>
> **同生共死模式**：若开启同生共死变体（coop_death_mode），任一玩家死亡即所有求生者输掉游戏（在玩家死亡流程末尾的全灭判定之前检查），详见 `04_事件流与变体.md`。

### 3.1 行动阶段

节点 9 行动阶段，玩家可执行 **4 个行动**（行动次数等于最大行动次数，通常为 4），可按任意组合执行以下行动，可多次执行同一行动。

**普通行动（每个消耗 1 行动次数）**：

| 行动 | 说明 |
|------|------|
| 移动 | 横向或竖向移动 1 格 |
| 抓牌 | 从求生者游戏牌堆抓 1 张牌 |
| 出牌 | 从手牌中打出 1 张牌（详见 `03_判定与术语.md` 使用卡牌一节） |
| 执行已在场卡牌行动 | 执行 1 张已经在游戏中的卡牌上的行动（如装备牌的填充物消耗、武器开火等） |
| 拾荒 | 根据当前地块颜色抓 1 张拾荒卡 |

**免费行动（不消耗行动次数，每回合各 1 次）**：

| 免费行动 | 说明 |
|---------|------|
| 制衡 | 每回合一次，弃掉 2 张求生者游戏牌，从求生者游戏牌堆抓 1 张新牌 |
| 交易 | 每回合一次，与另一名同地图块的玩家交易拾荒卡 |

**行动次数与结束**：

- 行动次数耗尽（行动次数为 0）时自动结束行动阶段。
- 玩家可主动选择结束行动阶段（即使还有剩余行动次数）。
- 实际由界面层驱动"等待玩家行动"流程，行动次数耗尽或玩家主动结束时返回。

### 3.2 迷你回合

立即执行行动（execute_action_immediately）：仅含行动阶段的迷你回合。保存当前阶段，将阶段临时切换为行动阶段，按指定次数执行行动，结束后恢复原阶段。常用于卡牌效果让玩家在回合外执行行动。

## 四、怪物行动

玩家面前的怪物行动时，按怪物卡进入求生者怪物区的先后顺序进行行动（先进入先行动）。

### 4.1 怪物行动流程（6 节点）

| # | 节点 | 系统行为 |
|---|------|---------|
| 1 | 怪物行动前 | 钩子节点（before_monster_act） |
| 2 | 怪物行动时 | 钩子节点（on_monster_act） |
| 3 | 怪物攻击前 | 钩子节点（before_monster_attack） |
| 4 | 怪物攻击时 | 钩子节点（on_monster_attack），并执行攻击。怪物根据射程对目标发动攻击，详见 `03_判定与术语.md` 射程一节 |
| 5 | 怪物攻击后 | 钩子节点（after_monster_attack） |
| 6 | 怪物行动后 | 钩子节点（after_monster_act） |

> **击晕例外**：被击晕的怪物在下次行动时直接清除击晕标记并跳过整个 6 节点流程；击晕仅持续到下次行动。

**攻击目标选择**：以纠缠玩家所在地块为中心，按射程确定攻击目标列表，对每个目标造成伤害（伤害来源为该怪物）。射程值为"只攻击纠缠玩家"（none）时仅攻击纠缠玩家本人，无需地块查询；其他射程值的含义见 `03_判定与术语.md`。

### 4.2 怪物死亡流程（3 节点）

当怪物生命值小于等于 0 时进入死亡流程。死亡流程不可取消。

| # | 节点 | 系统行为 |
|---|------|---------|
| 1 | 怪物死亡前 | 钩子节点（before_monster_death），输出"被某玩家击杀"或"被击杀"日志，发射怪物死亡信号 |
| 2 | 怪物死亡时 | 钩子节点（on_monster_death）。然后向所有玩家怪物区中的其他存活怪物广播"怪物死亡时"事件，使跨怪物监听技能（如僵尸女王、爆破机器人、方阵机器人等）能触发 |
| 3 | 怪物死亡后 | 钩子节点（after_monster_death）。从纠缠玩家怪物区移除该怪物，将其来源怪物卡放入怪物弃牌堆 |

## 五、胜利与失败判定

胜负判定由状态机的胜利条件检查流程（check_win_condition）和游戏的失败即时触发流程共同完成。

### 5.1 玩家死亡条件

当以下任一情况发生时，求生者死亡：

- 生命值小于等于 0（受伤致死）。
- 求生者游戏牌堆中没有卡牌且需抓牌时（牌堆耗尽致死）。

### 5.2 玩家死亡流程（3 节点）

玩家死亡流程（death）共 3 个节点：

1. **玩家死亡前**：钩子节点（before_player_death），输出"X 死亡了"日志，发射玩家死亡信号。
2. **玩家死亡时**：钩子节点（on_player_death）。
3. **玩家死亡后**：钩子节点（after_player_death），随后做以下清理：
    - 怪物区怪物置入怪物弃牌堆，等量怪物标记（最多 3 个）放回玩家当前地块。
    - 场上所有该角色的求生者游戏牌移出游戏。
    - 该名角色携带的所有拾荒卡按颜色洗回对应颜色的拾荒牌堆（装备区拾荒卡以其来源拾荒卡入堆）。

死亡流程末尾根据变体与全灭情况触发游戏失败：

- **同生共死模式**：开启同生共死变体（coop_death_mode）时，任一玩家死亡即直接以失败结算游戏（在全灭判定之前检查）。
- **全灭判定**：所有玩家死亡（all_players_dead）时以失败结算游戏。

### 5.3 胜利条件

胜利条件仅在玩家回合结束时检查（玩家依然会在回合结束前受到伤害）。胜利条件检查依次判断：

1. **任务目标完成**：由任务配置的胜利判定函数检查（自定义胜利条件代码 win_condition_code 编译后的判定）。
2. **面包车胜利判定**：
    - 若任务配置的"启动面包车所需燃料"（van_fuel_required）小于 0（取值为 -1 作为哨兵值，表示该任务不通过面包车胜利），跳过下面 3 项检查，直接以胜利结算。
    - 否则需同时满足以下条件：
        - 面包车燃料充足：地图中"面包车"地块的当前燃料值不少于任务配置的启动面包车所需燃料。
        - 所有存活玩家返回：所有存活玩家位于"面包车"地块上。
        - 面包车无怪物和怪物标记。

> 任务胜利条件总览、特殊胜利任务（任务 4 / 8 / 9 / 11）的胜利条件详见 `01_概述与任务目标.md` 第二节。

### 5.4 失败条件

失败条件即时触发，不需等到回合结束。包括：

1. **所有玩家死亡**：所有求生者被消灭，游戏失败。
2. **同生共死模式**：开启同生共死变体时，任一玩家死亡即所有求生者输掉游戏（详见 5.2 节）。
3. **怪物牌堆耗尽**：怪物牌堆重洗后仍为空（所有怪物卡都在场上），游戏失败。该判定在玩家抓怪物卡流程中触发。
4. **任务特定失败**：部分任务定义即时失败条件，如任务 8 潜行检定失败且玩家没有日记本时立即以失败结算。

> 失败结算统一通过游戏的"游戏结束"流程以失败结果触发；玩家死亡流程与抓怪物卡流程内分别在全灭判定与重洗后仍空判定中调用。

### 5.5 游戏结束流程的统一行为

无论胜利还是失败，游戏结束流程（详见 2.5 节）统一执行：状态置为游戏结束、停止计时器、保存最后回合玩家、清空当前回合玩家与回合队列、输出胜负日志、对每名玩家触发"游戏结束时"事件、设置游戏的"已调用游戏结束"标记与游戏结果字符串、发射游戏结束信号。

## 六、相关字段

状态机与游戏对象在运行时维护以下关键字段：

| 字段（英文键名） | 含义 |
|------|------|
| 当前状态（current_state） | 当前游戏状态枚举值 |
| 游戏结果（game_result） | 游戏结果枚举值，初值为 -1 表示未结束 |
| 当前回合玩家（current_player） | 当前正在进行回合的玩家；游戏结束后置空 |
| 最后回合玩家（last_player） | 游戏结束时保存的最后回合玩家，供结算场景高亮 |
| 回合队列（turn_queue） | 队首为下一个行动玩家，包含标准回合与额外回合 |
| 跳过标记（skip_turn_marks） | 玩家到是否跳过的字典，跳过一次性执行后移除 |
| 当前轮数（turn_number） | 所有玩家各执行一次为一轮，从 0 开始，首次填充队列时自增 |
| 同生共死模式（coop_death_mode） | 游戏对象上的变体开关，开启后任一玩家死亡即全灭失败 |
| 所有玩家死亡（all_players_dead） | 游戏对象上的查询方法，返回是否所有玩家均死亡 |
| 已调用游戏结束（game_over_called） | 游戏对象的标记，防止重复结算 |
| 任务配置（mission_config） | 游戏对象持有的运行时任务配置，包含启动面包车所需燃料与胜利判定函数等 |
